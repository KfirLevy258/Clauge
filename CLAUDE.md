# Working on BLINK

A paid desk display: an ESP32 CYD (320x240, Zephyr / C99 / LVGL 9) showing
Claude Code and Codex usage, fed by a Python daemon over USB serial. Shipped
hardware is in customers' hands, so a mistake here can brick a device that is
already on someone's desk.

Three parts: `firmware/` (the board), `pc/` + `claude_usage_bridge.py` (the
daemon and CLI), `tools/` (build, flash, release, fleet).

## Hard rules

**This repository is public.** Commit messages must never contain
`Co-Authored-By: Claude` or `Claude-Session:` — the second carries a session
URL. Install the hook that strips them, once per clone:

```sh
git config core.hooksPath .githooks
```

`core.hooksPath` is local config and is not cloned, so a fresh checkout has no
protection until you set it. Forgetting has already cost one history rewrite
and, a release later, six commits caught only at push time.

**`pc/` is standard library only.** No new runtime dependency, ever — not one.
The daemon ships frozen to customers, and every megabyte is theirs to
download. Reading a single eFuse bit once cost a third of the download because
it pulled in `cryptography`; `pc/efuse_probe.py` exists to explain that.

**Never log the contents of a serial buffer.** No byte ranges, slices, decoded
values, or surrounding bytes — in any log line, exception message, or stderr
print, at any level. This is not negotiable and applies to debug paths too.

**Never generate usage to refresh a reading.** Don't send messages in Claude
Desktop or Claude Code to make a number move: that spends the owner's real
quota. Use `pc/providers/scripted.py` or `BLINK_OTA_DIR`-style fixtures.

**Fixtures are generated by committed code, never captured from a real
machine.** A captured fixture carries somebody's real session content into a
public repo.

**Do not run `tests/ci/check_install.sh`, `tests/ci/check_claude_version.sh`,
or `tests/ci/check_update.sh` on a machine with a live install.** They are CI
scripts: they install, uninstall and reinstall the service for real, so on a
developer's own desk the board goes to HOST LOST while they are looking at it.
CI runners are the only place they belong.

Never create `.bak` files. Set `PYTHONDONTWRITEBYTECODE=1` on anything that
mutates the tree.

## The wire protocol

The board reads NDJSON lines and **drops an over-long line whole**, silently,
with no error on either side — the panel just stops updating while the daemon's
log keeps printing the message as sent. The budget is 512 bytes and a loaded
two-provider frame already measures 484.

So: every production writer uses `protocol.encode_checked()`, never plain
`encode()`. `encode_checked` was written for exactly this and once had no
production caller at all — only tests exercised it.

## Tests

```sh
python3 -m venv .venv-test          # 3.11+; a bare `python` may not exist
.venv-test/bin/python -m pip install \
    pyserial==3.5 esptool==5.3.1 ecdsa==0.19.1 certifi==2026.7.22 \
    pytest numpy Pillow
.venv-test/bin/python -m pytest tests/ -q
```

`tests/ci/check_factory.sh` shells out to `python3` and needs numpy and
Pillow, so on a machine whose system `python3` lacks them, run it as
`BLINK_PYTHON=$PWD/.venv-test/bin/python sh tests/ci/check_factory.sh`. The
other CI scripts have no such dependency.

**1459 passing** as of 2026-09-10. The first four packages are pinned in
`pc/requirements.txt` and are pinned on purpose; `numpy` and `Pillow` are only
needed by the logo and boot-animation encoder tests. CI runs the same
`pytest tests/ -q`.

`tests/conftest.py` redirects both `HOME` and `USERPROFILE` to `tmp_path` and
sets `BLINK_SKIP_SERVICE=1`, autouse, for every test. Read its docstring before
working around it — both fixtures exist because a test once booted out the
launchd agent of the person logged in.

**The sandbox has one hole:** a module-level constant computed with
`os.path.expanduser("~")` is evaluated at import, before any fixture runs, so
it points at the real home no matter what `conftest.py` does. Resolve paths
inside functions, not at module scope.

## Hardware

**Zephyr 4.3.x, SDK 0.17.4 — not 4.4.0**, which cannot build this firmware:
its mbedTLS 4.x dropped `mbedtls/sha256.h` (`src/ota.c`) and its LVGL moved
`gesture_limit` out of the public headers (`src/ui_settings.c`). The scripts
locate the workspace via `tools/lib_zephyr.sh`; `BLINK_ZEPHYR` overrides.

**Check `FLASH_CRYPT_CNT` before any flash.** Fused units exist, and writing a
plaintext image to a fused chip produces a board that will not boot until it is
flashed the other way. `tools/lib_efuse.sh` asks; `tools/burn.sh` refuses.

**A direct esptool write to slot 0 leaves the image unconfirmed.** MCUboot
test-boots it and reverts at about 90 seconds, which looks exactly like a crash
loop. Sign with `tools/sign_confirmed.py` (`imgtool sign --pad --confirm`);
`burn.sh` already does.

Firmware work is **not done when it builds** — done means flashed to a board
and boot-verified.

`tools/burn.sh` is the reference for stopping and restoring the daemon around a
flash. Note that `launchctl bootstrap` registers a job without starting it; a
restore also needs `launchctl kickstart -k`.

The board's auto-reset circuit is cross-coupled: EN is low only while RTS is
asserted and DTR is not; IO0 is low only while DTR is asserted and RTS is not.
A plain `serial.Serial(port)` open is safe, but pre-setting `dtr=False,
rts=False` before opening **reboots the board** — pyserial applies them after
the open, DTR first, and for that instant the board is in the reset condition.
See the long comment in `claude_usage_bridge.py` and
`docs/open-bugs/windows-usb-ota.md`.

## Style

On-screen copy is **sentence case**: every sentence the customer reads starts
with one capital letter and no more. The board keeps 47 characters of an error,
so say the thing that fits.

Comments explain *why*, with the measurement or the incident that produced the
rule — that is the house style throughout this codebase, and it is why the
comments are long. Match it rather than trimming it.

Commit messages: a plain subject line, then prose explaining what was wrong and
how it was found. No trailers (see the top of this file).
